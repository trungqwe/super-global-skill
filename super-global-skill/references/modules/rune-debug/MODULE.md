# rune-debug

1. Construct the fastest representative failing signal: existing test, CLI/API probe, trace replay or focused harness. Confirm it detects the reported failure before changing code.
2. Test one falsifiable hypothesis at a time; after repeated failed hypotheses, widen the evidence rather than repeat edits. Pass the proven cause and regression check into the authorized fix.

Use current session tools and repository conventions. Scale checks to risk; do not recursively load other skills or assume permission from this file.

For domain-specific detail beyond these steps, inspect [references/index.md](references/index.md) and read only the relevant source section.
