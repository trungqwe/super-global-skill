# rune-test

1. Test the public contract, realistic boundaries and failure paths using the repository's existing framework.
2. For a regression, prove the new check detects the defect before the fix and passes afterward. Avoid tests that merely repeat implementation text; report collected test counts.

Use current session tools and repository conventions. Scale checks to risk; do not recursively load other skills or assume permission from this file.
